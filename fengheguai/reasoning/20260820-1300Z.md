## t0008 · explore · keep · val_bpb 0.980245

- **best after:** 0.980245  ← new champion

**Hypothesis (pre-registered).** This run is data-limited rather than compute-limited: the loader reports epoch 2, so the 550M training tokens are roughly two passes over the same corpus, while MFU is already 40.6 percent. In that regime the binding constraint is how much of the corpus the model can commit to accessible memory, and the value-embedding path is exactly that mechanism, injecting a per-token learned value directly into the attention value stream. It currently runs on only 4 of the 8 layers. Extending it to every layer should give the model denser token-indexed memory and lower val_bpb, at almost no FLOP cost because value embeddings are gathers rather than matmuls and are excluded from the per-token FLOP model.

**Change.** One structural change on champion t0004: has_ve now returns True for every layer instead of only alternating layers, so all 8 blocks carry a value embedding and a ve_gate rather than 4. This roughly doubles value-embedding parameters from 16.8M to 33.5M (vocab 8192 by kv_dim 512 per layer). Depth, model_dim, HEAD_DIM 128, batch 2**18, the rescaled learning rates, the 512-token short window and all schedules are unchanged.

**Predicted effect.** Expected decrease of roughly 0.001-0.005 bpb versus champion t0004 at 0.981147 if token-indexed memory is the binding constraint under data repetition. The step count should fall only slightly, by a few percent, from the extra gathers and the larger AdamW optimizer state; if instead it falls sharply, the mechanism is bandwidth-bound and the comparison is confounded, which num_steps will reveal.

**Stated risk.** Doubling value-embedding parameters doubles their AdamW moment memory and gather bandwidth, so the step cost may exceed the quality gain. There is also a real chance the alternating pattern is deliberate and near-optimal, with dense value residuals over-constraining the value stream and raising val_bpb; that outcome would say the mechanism is already saturated at 4 layers and would redirect the search toward reducing rather than extending it.

## t0009 · refine · failed · val_bpb —

- **best after:** 0.980245

**Hypothesis (pre-registered).** Attention currently reads across document boundaries. The loader packs multiple whole documents into every 2048-token row and starts each row with BOS, so within a 512-token short window a large fraction of queries attend to tokens from a preceding, unrelated document. That cross-document context is pure noise for next-token prediction. Restricting attention to the enclosing document, by deriving cu_seqlens from BOS positions and switching to the flash-attention-3 varlen kernel, should remove that noise and lower val_bpb. This is the first node to change what attention may see rather than how much compute it costs.

**Change.** Document-boundary masking on champion t0008. GPT.forward derives document starts from BOS positions in the flattened batch and builds a cu_seqlens tensor; CausalSelfAttention and Block thread that descriptor through, and attention calls flash_attn_varlen_func with per-document sequence boundaries instead of flash_attn_func over whole rows. The sliding-window sizes, causality, capacity, dense value embeddings, batch 2**18, learning rates and all schedules are unchanged, so only the attention support set differs.

**Predicted effect.** Expected decrease of roughly 0.003-0.010 bpb versus champion t0008 at 0.980245, since document masking is one of the larger known corrections for packed-sequence pretraining and no earlier node has touched this mechanism. A smaller gain would indicate documents in this corpus are long relative to the 512-token short window, so few windows actually straddle a boundary.

**Stated risk.** The main risk is throughput, not correctness. The BOS scan uses nonzero, which forces one device synchronisation per forward pass and a torch.compile graph break, and cu_seqlens has a batch-varying length that is marked dynamic to avoid endless recompilation; if the varlen kernel is slower than the dense one at this shape, the step count will drop and could erase the quality gain, which num_steps will show directly. If the kernel rejects the call outright the node fails and the bounded debug stage repairs it from the traceback.

## t0010 · debug · keep · val_bpb 0.978165

- **best after:** 0.978165  ← new champion

**Hypothesis (pre-registered).** Unchanged from t0009: attention reads across document boundaries inside each packed 2048-token row, and confining it to the enclosing document should remove that noise and lower val_bpb. t0009 did not test this hypothesis at all; it aborted during compilation because torch._dynamo.mark_dynamic was called from inside GPT.forward, which dynamo traces, raising AssertionError on a forbidden callable. The repair moves that call into eager code so the same masking mechanism can actually run.

**Change.** Debug repair of t0009 with the mechanism intact. The cu_seqlens construction moves into a module-level build_varlen helper; the training loop calls it eagerly, applies torch._dynamo.mark_dynamic to the varying dimension there, and passes the descriptor into the compiled model through a new trailing varlen keyword on GPT.forward. When varlen is not supplied, forward still builds it internally, which keeps the locked evaluator path document-masked since prepare.evaluate_bpb calls model(x, y, reduction=none) and cannot pass the extra argument. Attention still uses flash_attn_varlen_func with per-document boundaries; capacity, dense value embeddings, batch, learning rates, windows and schedules are untouched.

**Predicted effect.** Same prediction as t0009: a decrease of roughly 0.003-0.010 bpb versus champion t0008 at 0.980245. The repair changes only where the descriptor is built, not what attention is allowed to see, so if the mechanism is real the gain should appear now.

**Stated risk.** Throughput remains the main risk: the BOS scan uses nonzero, forcing one device synchronisation per micro-step, and marking cu_seqlens dynamic yields a dynamic-shape graph that may compile to slower kernels; a drop in num_steps would offset the quality gain. The evaluator path builds the descriptor inside the traced region without a dynamic mark, so it may recompile a few times and then fall back to eager, which costs wall-clock but not training_seconds and cannot affect the locked score.
