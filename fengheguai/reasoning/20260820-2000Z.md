## t0045 · debug · discard · val_bpb 0.972759

- **best after:** 0.972704

**Hypothesis (pre-registered).** Unchanged from t0044: with QK normalisation fixing the norms of q and k, every one of the 48 heads is locked to the same 1/sqrt(head_dim) temperature, and learned per-head scales initialised at 1.0 should let each head choose its own sharpness and lower val_bpb. t0044 never tested that hypothesis because it aborted in the attention kernel with a dtype error, FlashAttention only supports fp16, bf16, and fp8_e4m3. The cause is type promotion rather than the mechanism: under autocast q and k are bf16 while the new scales are fp32 parameters, and elementwise multiply is not an autocast-listed op, so bf16 times fp32 promotes the product to fp32 and fa3 rejects the input.

**Change.** Debug repair of t0044 with the mechanism intact. The only change is that each scale is cast to the activation dtype at the point of use, q * q_scale.view(1, 1, -1, 1).to(q.dtype) and the same for k, so the multiply stays in bf16 and the kernel receives the dtype it requires. The parameters themselves remain fp32, so optimizer state and update precision are unaffected, and the cast is differentiable so gradients still reach them. Everything else is as in t0044: per-head q_scale and k_scale initialised to 1.0, registered as their own AdamW group at scalar_lr times 0.01, excluded from matrix_params so Muon never sees a 1-D tensor, with the parameter-count assertion updated.

**Predicted effect.** Same prediction as t0044: between a 0.002 decrease and parity versus champion t0037 at 0.972704, with step count essentially unchanged. Initialising at 1.0 keeps the network mathematically identical to the champion at step 0, so the mechanism is floored near parity and departs only if per-head temperatures earn it.

**Stated risk.** The repair addresses the reported error exactly and touches nothing else, so the residual risk is the mechanism itself rather than the plumbing. The likeliest null is redundancy: scaling a head of q is close to scaling the corresponding slice of the c_q projection, and only the RMS normalisation sitting between them makes the two different, so if that distinction is too weak the result lands at parity. A second possibility is that bf16 rounding of a scale near 1.0 quantises small updates, since consecutive bf16 values near 1.0 differ by about 0.0078 and the group learns at 0.005 per step, so early updates may be partly absorbed by rounding even though the fp32 master parameter continues to accumulate them.

## t0046 · explore · discard · val_bpb 0.972982

- **best after:** 0.972704

**Hypothesis (pre-registered).** Gating is the one control-path addition that has paid in this campaign, and attention output has none. The value-embedding path is gated per head by 2*sigmoid of a linear map on 128 residual channels, and widening exactly that gate from 32 to 128 channels produced the only champion improvement in twenty nodes. Attention output receives no such treatment: every head contributes to the residual stream with a fixed unit weight regardless of context, so a head that is uninformative for a given token cannot be attenuated except through c_proj, which is a fixed linear map shared across all positions. Adding an input-dependent per-head gate on the attention output, built exactly like the value-embedding gate and zero-initialised so it starts neutral at a gate value of 1.0, should let the model suppress unhelpful heads per token and lower val_bpb.

**Change.** Architectural change on champion t0037: each attention module gains attn_gate, a bias-free Linear from ve_gate_channels of 128 to n_head, whose zero-initialised weights make 2*sigmoid(0) equal 1.0 so the model starts mathematically identical to the champion. In forward, the fa3 output is multiplied per head by that gate before the reshape into c_proj, with the gate cast to the activation dtype to avoid the bf16 to fp32 promotion that broke t0044. The gate is a 2-D Linear so it joins matrix_params and is optimised by Muon exactly as ve_gate already is, requiring no change to the parameter-count assertion. This adds 128 times 4 weights per layer, about 6K across the model. The per-head temperature scales from t0045 are not carried forward, since they measured a null. Output softcap 10, value-embedding gate 128, rotary base 30000, depth 12, width 512, document masking, dense value embeddings, batch 2**18, all learning rates and every schedule are unchanged.

**Predicted effect.** Expected between a 0.002 decrease and a 0.001 increase versus champion t0037 at 0.972704, with step count essentially unchanged since the gate is one small matmul and one broadcast multiply per attention call. Zero initialisation floors the mechanism at parity, so it departs only if per-head attenuation earns it, the same design that made the t0045 null harmless.

**Stated risk.** t0032 is the cautionary precedent: widening the value-embedding gate input from 128 to 512 cost 0.002143, which says control-path capacity on this architecture has a real optimum and more is not free. This node adds a second gate rather than widening an existing one, so it is not the same coordinate, but the lesson transfers and a regression here would say the model already has as much gating as it wants. There is also a subtler risk that gating attention output partially duplicates what the value-embedding gate already does, since both modulate what enters the residual stream from the attention block, in which case the result is a null rather than a loss.

## t0047 · explore · discard · val_bpb 0.974299

- **best after:** 0.972704

**Hypothesis (pre-registered).** Capacity has been treated as closed because depth is bracketed at 12, with 10 costing 0.000807 and 14 costing 0.001519, but that bracket only ever varied how many blocks there are and never how capacity is allocated inside one. The allocation matters because the two routes have different prices. Adding two layers to reach depth 14 added about 6.3M matrix parameters but also two more value-embedding tables and two more attention stacks, and cost 13 percent of steps. Raising the MLP expansion from 4 to 5 adds the same 6.3M matrix parameters while adding no attention FLOPs and no value-embedding table, and should cost about 11 percent of steps. If capacity per step spent is what the depth bracket was really measuring, the cheaper route should land better than depth 14 did, and if MLP capacity is genuinely underprovisioned relative to attention it should beat the champion.

**Change.** Architectural change on champion t0037: the MLP expansion factor from 4 to 5 in both projections, so c_fc maps 512 to 2560 and c_proj maps 2560 back to 512, instead of 2048. Depth stays 12 and width stays 512, so the value-embedding tables, attention parameters and the rest of the model are untouched, which makes this a pure test of the attention-to-MLP allocation at fixed depth. The attention output gate from t0046 and the per-head scales from t0045 are not carried forward, both having measured at or below parity. Output softcap 10, value-embedding gate 128, rotary base 30000, document masking, dense value embeddings, batch 2**18, all learning rates, WEIGHT_DECAY 0.2 and every schedule are unchanged.

**Predicted effect.** Expected between a 0.001 decrease and a 0.002 increase versus champion t0037 at 0.972704, with the step count falling to roughly 1300 from 1465. The honest prior is a regression of about 0.001, by analogy with depth 14, since the two changes add identical parameter counts for similar step costs. What makes the node worth spending is that the prior rests on an untested equivalence between two different ways of buying capacity, and the depth bracket cannot distinguish them.

**Stated risk.** A hidden dimension of 2560 is a less conventional shape than 2048 and may hit slower GEMM kernels despite being a multiple of 128, which would show up as a larger step-count drop than the FLOP ratio predicts and would confound the allocation question with a throughput artefact; num_steps against the predicted 1300 will separate those. The zero-initialised c_proj and the uniform init on c_fc both scale with n_embd rather than with the hidden width, so the wider layer starts with the same per-weight scale and slightly larger activations, a small departure from the tuned initialisation that this node does not correct.
