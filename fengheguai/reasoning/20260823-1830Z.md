## t0359 · explore · discard · val_bpb 0.967134

- **best after:** 0.966202

**Hypothesis (pre-registered).** The output-gate line is characterised and I am leaving it. Four trials fixed its shape: all twelve layers must be gated, t0355 and t0356; it must act in the head basis, since t0357 gating the projected output lost 0.002844 of the 0.003139; and a whole head is the right unit, since t0358 subdividing into 32 channel blocks cost 0.000286 of mechanism on top of its throughput. What the gate does is decide, per token, how much of each head to emit. The untouched degree of freedom is the other half of the same decision: not how much of a head to emit, but how sharply that head looks in the first place. QK-norm pins the lengths of q and k, which is what makes training stable here, but it also removes the logit-scale freedom entirely, so every head at every token attends at one fixed temperature. Giving that back per head and per token lets a head be nearly uniform over its window on one token and sharply peaked on the next, which is a different mechanism from gating: it changes where attention goes rather than how much of the result survives.

**Change.** One mechanism added to champion t0353, alongside the output gate rather than replacing it. CausalSelfAttention gains q_temp, a bias-free linear map from the first 128 channels of the layer input to n_head outputs, built exactly like attn_gate beside it. In forward, immediately after q, k = norm(q), norm(k), the queries are scaled per head by 1 + 0.5*tanh(q_temp(x[..., :128])) with a trailing axis, so the multiplier is bounded to (0.5, 1.5) and sits at 1.0 at initialisation since the weight starts near zero. The bound is deliberately tighter than the output gate's (0, 2): attention logits carry no softcap, so an unbounded sharpen is a stability risk that the output path does not have. Placement after the norm matters, since applying it before would be normalised away. The output gate, the twelve gated layers, the head-granularity gate and everything else in the champion are untouched.

**Predicted effect.** Expected between 0.9655 and 0.9670. The throughput prediction is that this is close to free, because the multiply is pointwise on the output of norm, which is also pointwise, so Inductor should fuse them into one pass rather than adding a read and write as the output gate does when its producer is the FA3 kernel. I am flagging that prediction as unreliable rather than asserting it: this is my third throughput surprise in a row, having underestimated the gate cost threefold in t0353, predicted the wrong sign in t0357, and predicted zero for t0358 when it cost 1.28 percent. So the step count is again the first thing I will read, and if steps fall by more than the 0.07 percent noise floor then the fusion did not happen and the mechanism must be judged after subtracting the tax.

**Stated risk.** Stability is the main concern and the reason for the tight bound. Sharpening attention raises the largest logits, and this model relies on QK-norm to keep them controlled, so a temperature much above one could produce the kind of blow-up t0110 showed when the output softcap was loosened; if the run diverges or lands far above 0.97 I will treat it as a stability failure and retry at (0.75, 1.25) rather than abandoning the mechanism. The second risk is capacity, which this campaign punishes: this is a second per-head modulation reading the same 128 input channels as the first, and the model may simply not have the data to fit both. If it regresses mildly with steps intact, that is the capacity verdict and the follow-up is to test the temperature alone, with the output gate removed, to see whether the two mechanisms are substitutes rather than complements.

Attention-side per-head modulation is closed. This trial opens an axis the campaign has never touched. Every AdamW group in setup_optimizer passes weight_decay=0.0, so the token embedding, the unembedding and the value-embedding tables train with no regularisation at all, while every Muon matrix decays at 0.146. Those three tables are roughly two thirds of the parameters, and this budget sits near the point where the fixed dataset is seen about twice, which is exactly the regime where unregularised embedding tables can memorise. The reason this has probably never been tried is that a raw weight decay is not comparable across these groups: decoupled decay shrinks a parameter by lr*wd per step, and these learning rates span a factor of 300 from 0.735 on the embedding to 0.00245 on the unembedding, so a single shared wd would decay one table three hundred times harder than another. The quantity to hold fixed is the product, which is the same lesson this campaign already learned when a batch change broke the cumulative constants but not the time-indexed ones.

**Change.** One regularisation change on champion t0353. A new constant EMBEDDING_DECAY_RATE is set to 0.00238, which is exactly MATRIX_LR times WEIGHT_DECAY at the champion setting, so the embedding tables are asked to decay at precisely the rate the Muon matrices already do. setup_optimizer gains a small helper wd_for(lr) returning EMBEDDING_DECAY_RATE divided by that group's learning rate, and the three embedding-family AdamW groups now pass that instead of 0.0: the unembedding gets wd 0.97163 at lr 0.00245, the token embedding 0.00324 at lr 0.73485, and the value embeddings 0.00648 at lr 0.36742, so all three realise lr*wd = 0.00238. The two scalar groups, resid_lambdas and x0_lambdas, keep weight_decay 0.0 since decaying a residual mixing coefficient toward zero would silently shrink the residual path, which t0108 already showed this recipe dislikes. Because wd is fixed while the schedule scales lr, the effective decay tracks the learning-rate schedule exactly as it does for the Muon groups. No architecture changes, so throughput should be untouched.

A null means embedding capacity is not the binding constraint at this budget and the axis closes. The value is derived rather than guessed, which is deliberate: an arbitrary wd producing a null would be uninformative, whereas matching the rate the matrices already tolerate makes a null mean something.

**Stated risk.** The main assumption is that adamw_step_fused implements decoupled decay, shrinking p by lr*wd per step rather than adding wd*p to the gradient. I read the optimizer and the fused kernel takes a separate weight-decay tensor alongside lr, which is the decoupled signature, but I could not read inside the kernel itself. If it is coupled, the decay still acts in the same direction but is divided by the Adam denominator, so the realised rate would be smaller and unequal across groups; the signature would be a null far milder than expected, and I would then verify the convention before spending another trial.
