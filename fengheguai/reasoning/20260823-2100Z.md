## t0372 · explore · discard · val_bpb 0.964532

- **best after:** 0.964001

**Hypothesis (pre-registered).** Value-embedding compression is closed and the way it closed is informative. t0370 shared one table across all layers and lost 0.011430 of mechanism; t0371 restored per-layer maps through a rank-256 factorisation and recovered only 0.000909 of that, while paying 3.1 percent of throughput for twelve extra matmuls. So the value in those tables is not a shared token code viewed differently per layer. Each layer wants genuinely independent token-to-value content, and it is willing to spend 50.3M parameters, over half the model, to have it. That makes per-layer token identity the single most valuable mechanism this campaign has found, and it is currently injected into exactly one of the two paths a block has. Attention gets it through v = v + gate * ve. The MLP gets nothing: it sees the token only through the residual stream, filtered by every layer below it. If per-layer token identity is what this model is short of, the path that lacks it is where the next unit of it should go. The run also reaches only epoch 1, so this is not a regime where added embedding capacity is obviously overfitting; the same block already responds well to mild decay rather than to being smaller.

**Change.** One mechanism added to champion t0367, mirroring the value-embedding path onto the MLP. A new mlp_embeds ModuleDict holds one nn.Embedding of vocab_size by n_embd per layer, matching where has_ve is true, which is every layer. MLP.forward takes an optional me tensor and, after c_proj, adds gate * me where gate is 2*sigmoid(me_gate(x[..., :128])) and me_gate is a bias-free Linear from 128 channels to 1, zero-initialised so the gate starts at exactly 1.0 as ve_gate does. Block.forward passes me through, and GPT.forward gathers it per layer alongside ve. The tables are treated exactly like the value embeddings rather than given new hyperparameters: they join value_embeds_params so they share the AdamW group, the value-embedding learning rate of 0.3, and the decay at lr*wd = 0.00238 that t0367 established; they are initialised uniform at plus or minus sqrt(3) for RMS 1 and cast to bf16 in the same loops. This adds 50.3M parameters, taking the model from about 96M to about 146M. The me_gate weights sit inside transformer.h so Muon picks them up and the parameter-count assertion stays balanced.

**Predicted effect.** Expected between 0.9600 and 0.9680 against champion 0.964001, a wide band because this is the largest capacity addition of the session and its two effects pull opposite ways. Throughput should fall by roughly 3 percent: twelve more gathers, a gate and an add per layer, and optimizer state for 50.3M more parameters, so I expect steps near 2690 and will subtract the throughput term with the calibrated slope of -0.0586 before judging the mechanism. For this to take the championship the mechanism must clear about 0.0018 just to pay that rent. A clear decrease would say per-layer token identity is the binding constraint and the next question is how much more of it the model wants; a regression with the mechanism residual near zero would say the MLP simply has no use for token identity, which given how much the attention path values it would be a genuinely surprising asymmetry between the two.

**Stated risk.** The obvious risk is capacity: t0367 showed this block already benefits from being regularised, so adding another 50.3M unregularised-by-default parameters could hurt, which is why they inherit the same decay rather than none. The second risk is that I am reasoning by analogy from a mechanism whose own explanation I do not have. I know per-layer value embeddings are worth a great deal and cannot be compressed; I do not know why, and the MLP analogy assumes the reason transfers to a path with no softmax, no heads and no value vector. If the mechanism residual comes back near zero rather than negative, that assumption is what failed, and the honest follow-up is not to tune this but to ask what the value path has that the MLP path does not.

## t0373 · explore · discard · val_bpb 0.965764

- **best after:** 0.964001

**Hypothesis (pre-registered).** t0372 answered the question it was built to answer and the answer was yes. Giving the MLP its own per-layer token-identity tables produced a mechanism residual of -0.002296, comparable to the value-embedding decay that won a championship, so the analogy transferred: the MLP does want per-layer token identity, and its absence was a real gap. What defeated the trial was price. Those tables added 50.3M parameters and cost 4.71 percent of steps, a throughput tax of +0.002826, so a working mechanism lost by 0.000530. That is a better failure than a dead direction, because it converts the problem from finding a mechanism into paying less for one I have measured. The cheap route is already present in the model. Every layer already gathers a per-layer token-to-512 table, its value embedding, and t0370 and t0371 established that this table is per-layer and cannot be shared or factorised, which is exactly the property the MLP injection needs. So the MLP can read that same tensor through its own gate: no new tables, no new gather, and the only added work is one gate and one fused multiply-add per layer. If the mechanism in t0372 was about the MLP seeing token identity at all, rather than about seeing a second independently-learned copy of it, this should keep most of the -0.0023 at a small fraction of the cost.

**Change.** One mechanism added to champion t0367, reusing existing state rather than allocating new state. MLP.forward takes the layer's value embedding and, after c_proj, adds gate * ve where gate is 2*sigmoid(me_gate(x[..., :128])) and me_gate is a bias-free Linear from 128 channels to 1, zero-initialised so the gate starts at exactly 1.0 as ve_gate does. Block.forward passes the ve it already receives into the MLP. The separate mlp_embeds tables from t0372 are not carried over, which the edit asserts rather than assumes. Total added parameters: twelve gates of 128 by 1, or 1536 in a 96M model. The value embeddings keep their existing role in the attention path unchanged, along with their optimizer group, learning rate and the decay from t0367.

**Predicted effect.** Expected between 0.9620 and 0.9648 against champion 0.964001. The throughput cost should be roughly a gate and one full-width fused multiply-add per layer, which the bandwidth model prices near 1.4 percent, against 4.71 percent for t0372, so the tax should be near +0.0008 rather than +0.0028. If the mechanism keeps even half of t0372's -0.0023 this takes the championship. The informative comparison is not against the champion but against t0372: a mechanism residual near -0.0023 means the MLP wanted token identity as such and the second copy was pure waste; a residual near zero means it specifically wanted an independently-learned copy, and the -0.0023 came from the new tables being free to encode something the value path does not.

**Stated risk.** The value embedding is now read by two consumers with different objectives, the attention value path and the MLP output, so its gradient is the sum of two demands and it may end up serving neither as well; that would show as a regression rather than a null, and would be a real finding about why t0372's separate tables were worth their parameters. A second risk is that the two paths are not independent in the way I am assuming: ve already enters the residual stream through attention, so adding it again after the MLP is partly a second injection of the same signal into the same stream within one block, which the resid_lambdas and the attention output gate may already be positioned to supply. If this regresses I will not tune the gate; the informative follow-up is t0372's mechanism at reduced width, per-layer tables of vocab by 128 projected up, which keeps the independent copy while cutting its cost by four.
