**Hypothesis (pre-registered).** Every tunable constant in this model has now been varied at least twice across 428 nodes -- aspect ratio, head dim, batch size, all five learning rates, Adam betas, EMA start and decay, warmup, final LR fraction, depth, device batch, table decay, output softcap, rope base, weight decay, warmdown, window pattern and short-window divisor. The knob space is saturated, so this is a mechanism.

The fa3 kernels accept a softcap argument that the model never passes. flash_attn_func and flash_attn_varlen_func both default it to 0.0, meaning disabled, and when set they apply sc*tanh(scores/sc) to the attention logits inside the fused kernel. The model already softcaps its OUTPUT logits at 13 -- a value tuned across seven trials -- but has never capped attention scores, which is a different quantity with a different failure mode. Output capping bounds how confident the model may be about the next token; attention capping bounds how sharply a query may concentrate on a single key. In a 12-layer model where 8 of 12 layers see only a 256-token window, a head that saturates onto one nearby key wastes its capacity, and the mechanism that won this campaign's gating trials was precisely about attenuating retrieved content that is irrelevant to the current token.

The reason this is worth a slot rather than another knob is that it costs nothing. The cap is applied inside the fused kernel, so no intermediate reaches memory. This campaign's cost model says a full-width elementwise op per layer buys ~2.8% of steps in debt; this buys zero, so the entire raw delta is mechanism.

**Change.** One kwarg at two call sites: softcap=30.0 added to fa3.flash_attn_func and fa3.flash_attn_varlen_func. No new tensors, no new parameters, no change to any Python-level tensor operation -- the cap happens inside the kernel. The edit script asserts exactly two un-softcapped call sites exist, refuses if a cap is already present, and rejects a value of 0.0 since that is fa3's disabled sentinel and would be a silent no-op. Dry-run against the champion source confirmed both sites patch to valid syntax. Step count should not move.

**Predicted effect.** Uncertain in sign, which is what makes it worth running. 30 is a deliberately loose cap: it leaves ordinary attention logits untouched and only bends the extreme tail, so it should be closer to a safety rail than a regularizer. If attention saturation is costing this model anything I expect -0.001 to -0.003; if scores rarely reach 30 the result will be a clean null and I will have learned the operating range rather than nothing. Zero throughput cost by construction, so the raw delta is the mechanism and the ~0.0012 n=1 floor applies directly. Step count read first as always -- a kernel kwarg cannot legitimately move it, so a deviation beyond ~0.5% means contention and voids the comparison.

**Stated risk.** Implementation risk is low and dry-run verified. Two real risks. First, tanh softcapping interacts with the bf16 range of the attention logits; if scores routinely exceed 30 the cap becomes a hard nonlinearity rather than a tail bend and could destabilise early training, which would show as a loss spike -- the existing fast-fail on NaN or loss>100 catches the catastrophic case but not a mild one. Second, and the reason I chose 30 rather than a tighter value, is that a null at a loose cap does NOT close this axis: it would only mean scores rarely reach 30. Reading a loose-cap null as 'attention softcapping does not help' would repeat the extrapolation error this campaign has already made three times, so a null here routes to a tighter value rather than to abandoning the mechanism.
