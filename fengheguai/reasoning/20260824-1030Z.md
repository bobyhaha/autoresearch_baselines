Two things make it worth a slot now rather than earlier. First, t0440 demonstrated how tightly this model is coupled to its initialisation: a single matrix left on PyTorch's default init scored 1.0446, worse than the original baseline, from a change that was otherwise parameter-matched. A model that sensitive to one matrix being mis-scaled may not be sitting at the optimum for the scale all of them share. Second, s interacts with the zero-initialised c_proj matrices: every residual branch starts at exactly zero output, so s controls the scale of the features the branch learns to project from rather than the scale of its initial contribution. That decoupling is unusual and means the usual variance-preservation argument for sqrt(3)/sqrt(fan_in) does not straightforwardly apply here.

1.25 is a deliberately modest step. The point is to find out whether the axis is live at all before spending trials locating an optimum on it.

Value embeddings, wte, lm_head and the gate matrices keep their own separate scales, untouched. Compile mode reverts to default. Dry-run against champion source parsed.

**Predicted effect.** Genuinely unknown in sign; this is a probe, not a directional bet. Zero throughput cost -- initialisation does not change any per-step work -- so the raw delta is the mechanism plus the +0.00067 compile handicap, and steps should move only by the ~1.14% the revert forfeits.
My expectation is a null inside the floor, because sqrt(3)/sqrt(fan_in) is a well-motivated default and Muon's orthogonalised updates should wash out initial scale within a few hundred steps. If it is a null, that is a real finding given t0440: it would mean the model is sensitive to a matrix being mis-scaled RELATIVE to its neighbours, not to the common scale, which is a much more specific and useful statement than 'initialisation matters'.

**Stated risk.** Low implementation risk -- one arithmetic expression, dry-run verified. The interpretive risk is that this is a knob on an axis I have argued is saturated, and I should be honest that its main justification is virginity rather than a mechanism story. If it nulls I will not test 0.8 as a reflex; the campaign has spent enough trials on knobs, and one clean null on a never-varied constant is a reasonable place to stop.

Decay SHAPE at held mean is this campaign's most productive family: it won four separate times -- table decay flat->linear->squared, matrix decay linear->squared, the value-embedding decay ramp, and warmdown -- always at zero throughput cost, because reshaping a profile whose mean is fixed adds no work. This run ramps the lerp coefficient from 1.5x to 0.5x of (1-EMA_DECAY) across the averaging window, mean held exactly. Early in the window the average tracks the live weights more closely; late it has longer memory, so the final average is a smoother estimate over the settled, low-learning-rate region that warmdown produces.

I chose 1.5x->0.5x rather than the literal 2x->0 analogue of the other four wins after working out what the extreme does: an alpha reaching zero freezes the average outright, so the final steps -- the best-annealed ones -- would contribute nothing and the result would be a mid-window snapshot. That is a pathology rather than a shape test, and it would have looked like evidence against shaping when it was really evidence against freezing.

No new parameters, no new tensors, no change to any GPU kernel -- the coefficient was already a scalar multiply inside lerp_. Compile mode reverts to default for the wall-clock reason. Verified `progress` is in scope at the EMA block (set at line 632, used at 655).

**Predicted effect.** Zero throughput cost by construction, so the raw delta is the mechanism plus the +0.00067 compile handicap, and steps should move only by the ~1.14% the revert forfeits.
I am genuinely unsure of the sign and want to say why, because the analogy to the four prior wins is weaker than it looks. Those shaped a SHRINKAGE schedule, where front-loading means more regularisation early. This shapes an AVERAGING coefficient, where the trade is bias against variance: longer memory late reduces variance but averages in staler weights. Given warmdown anneals the learning rate to 10% by the end, the late weights are the good ones, and biasing toward earlier ones could easily cost more than the variance it saves.
Expectation: -0.001 to +0.001, most likely a small null. If it loses, the opposite ramp (0.5x -> 1.5x, short memory late) is the natural follow-up and is a genuinely different hypothesis rather than a reflex second point.
