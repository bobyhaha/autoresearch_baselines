## t0461 · recombine · failed · val_bpb —

- **best after:** 0.961216

**Hypothesis (pre-registered).** The token-embedding initialisation scale has never been varied: wte is set to normal(0, 1.0) in all 457 nodes, while lm_head's std was tried once at 0.01 and every other init in the model is either derived from fan-in or chosen for a stated reason.

I want to be precise about what this can and cannot do, because the obvious framing is wrong. The forward pass is scale-INVARIANT to wte's init: x = wte(idx) is rms_norm'd immediately and x0 is taken after that norm, so at step 0 the network computes exactly the same thing at any wte scale. This is not a 'relative mis-scaling' change of the kind that produced t0440's catastrophe, and I should not sell it as one.

What it changes is optimisation. The embedding group runs at lr 0.6 with weight_decay 0, so the init scale sets the ratio of update size to weight size -- how far the embedding can reorganise from where it started within 2800 steps. Halving the scale doubles the relative step size. That is a real degree of freedom and it is the one axis of this model's initialisation that nobody has probed, but its expected effect is modest by construction.

**Change.** One argument: wte init std 1.0 -> 0.5. No change to the forward pass, no new parameters, no change to the traced graph. max-autotune is retained, since initialisation runs before torch.compile and the inductor cache still hits -- so unlike the structural probes this is an unhandicapped comparison against the champion. Dry-run against champion source verified.

The forward pass cannot see the change at all, and Adam is scale-adaptive in its update magnitude, so most of the effect I am reasoning about is already normalised away by the optimiser -- what survives is the interaction with the fixed lr and the absence of decay on this group.
